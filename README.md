# LLM Serving Performance Lab

A measurement-driven investigation of how **scheduler token budget**, **concurrency**, and
**prefix reuse** interact in vLLM — and of what changes on the GPU when they do.

> **Within the tested regime, the latency–throughput tradeoff of `max_num_batched_tokens`
> depends on concurrency, prefix-cache reuse, and remaining local prefill work.**
> There is no single setting that wins across all of them.

```
Exp08  Behavioral observation          does the MBT effect depend on concurrency?
          │
          ▼
Exp12  Profiler localization           what changes on the GPU?
          │
          ▼
Exp11  Interaction experiment          manipulate remaining local prefill work and re-test
```

## Three numbers

| Experiment | Result |
|---|---|
| **Exp08** — C8, MBT4096 vs 2048 | **TPOT −4.29%**, **throughput +3.64%**, TTFT essentially unchanged |
| **Exp12** — nsys, MBT2048 vs 4096 at C8 | `prepare_prefill` markers **9 → 5**, final prefill marker **≈655.7 ms earlier**; steady-state decode **NOT faster** (34.200 vs 34.412 ms spacing) |
| **Exp11** — MBT4096 vs 512 | throughput advantage **+6.88% → +0.25%** as local compute decreases **≈2020 → 112 tokens/request**; TTFT flips to **+21.62% penalty** |

The chain is `consistent with` / `associated with` / `converging evidence` — **not a proof**.
Exp12 profiled three conditions, not the full factorial, and no scheduler-internal measurement
was taken.

---

## Why this exists

`max_num_batched_tokens` (MBT) is a **static server flag** — changing it requires restarting the
engine. Practitioners still have to pick a value. The usual advice ("bigger is better for
throughput") is a statement about *one* traffic mix.

This repository is the measurement infrastructure and the evidence behind a narrower claim:
that the right MBT is **workload-dependent** within the regime tested here, and that the reason
is traceable to **remaining local prefill work** rather than to decode speed.

## Scope and honesty notes

These are load-bearing — please read them before quoting any number above.

- **The workload is text serving.** The model `Qwen3-VL-8B-Instruct` is multimodal, but **no
  images were served** in any experiment here. This is not a multimodal-serving result.
- **Single GPU.** All formal experiments ran on one **RTX 3090** at a **220 W** power limit,
  under WSL2. Results do **not** transfer automatically to H100/A100 or to multi-GPU serving.
- **Exp12 profiled selected conditions, not the full factorial.** Three conditions
  (C1×MBT2048, C8×MBT2048, C8×MBT4096). The mechanism reading is therefore *converging
  evidence*, not a direct causal proof.
- **Completion length is fixed at 128 tokens**, so `request/s` and `output tok/s` are
  **mathematically coupled** — they are not two independent confirmations.
- **`P0` is the control level: no intended application-level shared prefix.** Its observed cache
  hit ratio is ≈1.2–1.4%, not literally zero. Do not read `P0` as "cache disabled".
- **`P0` throughput vs `PHIGH` (~+104%) is a prefix-cache reuse treatment effect**, not a
  scheduler-tuning result. It should never be quoted as an optimization win.
- **Synchronized bursts, not a real arrival process.** Concurrency here means *N requests
  released together*, not Poisson arrivals.
- **Relative comparisons only.** Absolute latencies are specific to this machine, this vLLM
  build (0.28.0), and this power cap.

## Raw profiler captures

**Raw profiler captures are omitted because of size.** The `.nsys-rep` / `.sqlite` traces are
hundreds of MB and are not useful without the matching GPU. This repository instead contains:

- the profiler **recorded settings** plus a clearly labelled **reconstructed** invocation,
  and the workload definitions (`experiments/exp12_decode_profiling/`),
- the **post-processing script** (`analyze_timeline.py`),
- the **machine-readable timeline summary** and hypothesis status (`results/`),
- the **figures** derived from them.

## Environment

System dependency (not installable via pip): **NVIDIA Nsight Systems ≥ 2024.5**
used here with `CuptiUseRawGpuTimestamps=false` under WSL2.

Python dependencies are in [`requirements.txt`](requirements.txt); configurable paths are in
[`env.example`](env.example). See [`docs/reproduction-guide.md`](docs/reproduction-guide.md).

## Provenance

The code in `common/` and `experiments/` is a **copy** of the frozen scripts that produced the
formal campaign. The originals are unmodified. Every change made during public-repo preparation
— there is exactly one class: absolute host paths replaced by environment variables — is listed
in [`docs/public-code-changelog.md`](docs/public-code-changelog.md). No measurement, scheduling, or
statistical logic was altered.

Evidence boundary: results in `results/` are **aggregates derived from the frozen formal
artifacts**; they are not the raw per-request logs. The raw logs stay private (size + they
contain host paths).
